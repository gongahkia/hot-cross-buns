# Markdown workspace and recovery

The app's working document is now the exact UTF-8 Markdown source described in [MARKDOWN_FORMAT.md](MARKDOWN_FORMAT.md). The default file is `Planner.md`. Dated entries, undated lists, ordinary prose and the terminal scratchpad belong to that one document. Appearance, local view preferences and credentials remain outside it. Immutable revisions are companion recovery artifacts; unresolved branches can contain work absent from the latest `Planner.md` projection.

Expensive browser validation and edit preparation run in a bounded worker, with full synchronous validation as a fallback when worker infrastructure is unavailable. Queued edits preserve ordering and reject stale results; parsing never commits browser or provider state on its own. Scratchpad save/capture prepares a full candidate before an atomic source/revision check in IndexedDB. See [parser performance and verification](PARSER_PERFORMANCE.md).

## Editing and content ownership

Existing entry/detail controls, completion, recurrence, spans, moves and capture promotion use `journalDocument.ts` to patch intended source ranges and validate the complete candidate. Derived task arrays are rebuildable views. They cannot replace source on reload, and the TXT serializer and merge are not runtime fallbacks. Untouched prose, tables, code, comments, spacing, line endings and metadata spelling survive structured edits. A changed metadata field can deliberately regenerate that entry's metadata block. Missing entry IDs are inserted when an operation requires identity; existing IDs survive ordinary moves and title edits, and copies receive new IDs.

The dated/undated views edit Markdown title text. Version 2 adds recursive outlines and expandable body notes with safe CommonMark/GFM previews; version 1 keeps its direct-detail semantics until an explicit upgrade. **Enable deeper outlines** is available through item actions or by searching Commands. Its preview shows the complete upgraded source and any ancestor checkbox changes. Enabling it is one normal undoable source transaction, checked against the original source before saving. Unsupported clients reject the newer document format; database schema 4 and revision protocol 2 remain unchanged.

Outline menus offer nested tasks/notes, indentation, outdentation, movement, promotion and branch deletion. Alt+ArrowUp/Down/Left/Right provide equivalent move/outdent/indent actions while editing an outline title; Tab retains normal focus navigation. Moves and promotions retain entire subtrees and body content. Descendant titles and body text participate in palette search. Body previews load on expansion and fall back to source above 40,000 characters or deeply nested content. HTML stays literal, unsafe links are inert, and images are represented by their alt text without fetching them. Mermaid and mathematics remain source/code content. Backlink navigation and day/week/month calendar views remain later stages in [the plan](MARKDOWN_PLANNER_PLAN.md).

Body notes use explicit Save/Cancel controls. Dirty inline editors hold the normal editing lease even after focus moves to their buttons. Session checkpoints are scoped to document/entry/source position and retain their original full-source/body/title baseline; a changed document requires review even when the current node has the same title and body. Invalid drafts remain editable and downloadable, and checkpoint quota errors keep the editor open. A session checkpoint is not a backup. Exotic structures that cannot be represented by a structured control must be edited in source rather than discarded.

Type **source** in Commands to open **Edit Markdown source**. It is hidden from the empty palette. Saving checks the original saved source, document identity and full grammar, then uses the normal durable journal transaction and undo path. It cannot silently replace a newer document. Use import/review for a different document identity. Invalid drafts stay editable and downloadable; validation does not make them saved journal content. Source and import-review drafts are tab-session checkpoints, flushed after a short debounce and when closing. On session-storage quota failure, keep the editor open and download the draft; a session checkpoint is not a backup. Reloaded stale drafts retain their original baseline and cannot become an unconditional overwrite.

The scratchpad is now shared content. Text saves and capture promotion modify the same canonical document in IndexedDB. A capture cut plus destination insertion is one transaction and one undoable document operation; redo includes both. A failed scratchpad queue stays available when switching views. Retry applies it against the latest task document, while a newer scratchpad edit requires recovery rather than overwriting. Incoming sync/history/source replacement respects active scratchpad drafts and failed writes. A local quiet period limits publication churn, but full-snapshot retention still applies.

## Conflicts and recovery

Single-file mode uses a conservative source merge. Disjoint source edits can merge when they do not touch the same semantic field. Titles are atomic; completion/metadata/detail-checkbox changes share a progress group; each detail title and the whole scratchpad are atomic. Concurrent complete entry insertions can combine only with distinct stable IDs and a valid resulting document. Ambiguous changes require review; the merge never reserializes arbitrary Markdown through task arrays.

Protected revision mode retains its stricter rule: concurrent heads require explicit review even when a source merge looks possible. Review offers complete browser/file sources and original downloads. **Keep both** is offered only for one non-recurring conflicting entry whose surrounding sources match exactly; its copied entry receives a new ID. Other cases use browser/file selection or an explicitly validated manual merge. A stale file, browser source, branch or link generation is checked again before commit. Applied doctor repairs retain the original observed source in comparison recovery. **Check file** validates; only **Apply import** commits.

History restoration includes the shared scratchpad and arbitrary source content. Preferences stay local. A complete immutable revision using protocol **2** precedes projection writes, with unchanged identity, ancestry, integrity, retry, discovery, retention and account-isolation safeguards. See [REVISION_SYNC.md](REVISION_SYNC.md). This cannot reconstruct an arbitrary external edit overwritten before observation, or confirm another device's cloud delivery.

## Earlier developer workspaces and rollback

IndexedDB remains named `hot-cross-buns-v1`, at schema **4**. The upgrade archives every old state and scratchpad record under `legacy-txt:` in its original store, in the same upgrade transaction. That includes file handles, baselines, pending submissions, revision ledgers and creation tickets. They are kept for recovery and are not replayed, converted into provider writes or silently relinked.

An existing TXT workspace must explicitly choose **Convert saved workspace** or **Start an empty Markdown workspace**. Preview and recovery downloads come first. Conversion maps the saved item fields and includes the formerly private scratchpad; the UI explains that it becomes shared when linked. Both choices retain the archive. Earlier external files and revision-1 history stay untouched. Link a new `.md` file/folder or Drive file after the transition; do not rename a TXT file and pretend its old history is protocol 2. A scratchpad-only workspace also requires this choice. There is no permanent TXT file-import compatibility mode.

The database upgrade fences older versioned openers. Finish/export unsaved old tabs and close them if the upgrade is blocked. Corrupt/unsupported canonical Markdown stops startup before structured editing or provider writes and offers a raw browser recovery download; stale cached task arrays are not accepted in its place. If the upgrade itself aborts, recovery opens the existing database without requesting a schema change and exports its original records in a read-only transaction.

A rollback must retain the **version-4 opener, exact-source state and baseline model, shared scratchpad transactions, protocol-2 validation/publication and protected-target guard**. Keep pending logical and provider identities, archived legacy records, creation tickets, review generations and all remote history. Earlier version-3 code cannot open this database or interpret the new history; the previous revision-era compatibility commits alone are insufficient. Do not lower/delete the database or downgrade envelopes to force a rollback. The complete runtime boundary is `b42be7e`, plus `1d64076` for recovery after an aborted upgrade. Prefer rolling back later UI changes while keeping this storage/sync compatibility layer, or export Markdown and recovery data first into a separate test profile.

## Verification boundaries

`journalDocument`, `journalMerge`, `markdownPlanner`, coordinator and revision tests exercise source preservation, mapping, complete shared captures, branch races, delayed discovery and interrupted publication. `markdown-runtime.spec.ts` exercises actual IndexedDB, explicit upgrades, raw corruption recovery, draft reload/staleness, quota failures, capture undo/redo and exact exports. Existing provider suites exercise substituted native pickers and mocked Google services, not physical-device delivery. The Python converter's output is checked by the real Markdown parser in `googleMarkdown.test.mjs`.

Resource limits remain 5 MiB / 100,000 lines per document and 1,000 revisions / 64 MiB of history, with no automatic pruning. Parser benchmarks use 10,000 entries; browser tests separately check 1,200 visible entries. These are bounded regression checks, not a universal speed claim. See [the parser dependency correction](PARSER_PERFORMANCE.md). Real Google authorization, Nextcloud/Dropbox/Syncthing clients, physical devices, native permission dialogs and non-Chromium browsers need separate validation.
