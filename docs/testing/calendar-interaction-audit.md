# Calendar interactions and daily-driver audit

Review date: 22 October 2026. Mode: **full**.

The four requested interaction improvements are implemented. This audit does **not** yet recommend an unrestricted daily-driver sign-off: remaining issues affect task completion, native item navigation, keyboard access, and confidence in Google-backed edits.

## Scope and implementation boundaries

Reviewed the production Electron renderer, its calendar/event/task inspector paths, shell navigation, registered IPC, source projections, scheduling, recurrence, undo, and Google sync boundaries. Compared the recovered `experiment/reference-cal` prototype (last version `54bc101`, removed by `c932d67`) with the live renderer. The prototype supplied presentation and interaction ideas; its sample accounts, in-memory events, persistence, and recurrence model were not imported.

Framework: React 19, Electron 33, Radix menus/dialogs, Motion, Tailwind utilities and the existing CSS variables in `src/renderer/src/styles/index.css`. No new styling or data framework was introduced. Existing IPC namespaces, storage, undo and sync remain in place; the backend change extends recurrence updates within the existing service.

Runtime review uses disposable local accounts in the production Electron build on macOS. It covers Calendar, inspectors, search, overflow, Tasks, Notes, Settings, light/dark themes, and narrow layouts through the existing workflow suite. Provider-specific behavior is reviewed in code and integration tests; a live Google account, installed/signed release, Windows/Linux desktop, and screen-reader session were **not verified** in this run.

| Category | Evidence inspected | Result |
| --- | --- | --- |
| Typography | Month chips at 1180×760 and 850×700; narrow menus; populated calendar/search/task/note screenshots | Month titles become difficult to identify at narrower widths; note-list timestamps crowd titles; see remaining findings. Full accessible labels and hover titles exist. |
| Surfaces | Both themes; inspector overlay; event menus; recurrence and overflow dialogs; painted timeline rectangles | Context menus fit the viewport. Overflow focus and small calendar targets remain concerns. |
| Animations | Real Electron menu playback at 10% through CDP `Animation.setPlaybackRate`; reduced-motion check; existing view/inspector transition suite | New menu playback and reduced motion verified. Drag previews have a static range label and Escape instruction. No per-pointer-frame animation was added. |
| Icons | Shared Lucide icons, accessible labels, completion states and new menu actions | Existing icon family and `currentColor` preserved. No new icon-specific finding. |
| Performance | Bounded calendar DOM; latest-viewport loader test; renderer six-window and worker three-range caches; populated workflow suite | Bounds retained. One viewport request plus its latest replacement; scroll-position writes are debounced. Observed populated transitions were 310–675ms; five of eight missed the 400ms comfort target while all passed the 1500ms regression ceiling. These are bounds, not universal latency guarantees. |

## Remaining findings

### Trust, feedback and product behavior

| Severity | Location | Before | After | Why |
| --- | --- | --- | --- | --- |
| HIGH | `src/main/services/coreStore.ts:892`; `src/renderer/src/features/core/screens/calendar/useCalendarEventInspector.tsx:685` | Calendar ingestion does not retain Google's `accessRole`; event editors and gestures consequently have no calendar-write capability to check. **Code-confirmed; live reader-calendar failure not exercised.** | Preserve calendar permissions in the existing calendar model, expose capability to the renderer, and make read-only events visibly read-only. | Prevent misleading affordances: shared/read-only calendar users can otherwise attempt edits that only fail during delivery. This needs a small existing-service extension, not a parallel backend. |
| HIGH | `src/renderer/src/features/core/screens/calendar/CalendarHeader.tsx:98`; `CalendarEventChips.tsx:359`; `useCalendarRangeLoader.ts:7` | The calendar status live region is empty, chips do not render their `mutationState`, and range loading exposes an error but no pending state. Local save and cloud delivery are visually easy to conflate. | Show a quiet loading/cached state, distinguish queued/failed changes on affected items, and link failures to existing retry/conflict controls. | Trustworthy feedback: a blank loading range should not imply free time, and a local edit should not imply Google accepted it. Existing global diagnostics are useful but insufficient at the point of editing. |
| HIGH | `src/renderer/src/features/core/viewModelSource/sourceBuilder.ts:211`; `CalendarEventChips.tsx:236`; `CalendarView.tsx:334` | **Reproduced:** completing a scheduled task's calendar block stamps event completion while the original task remains `active`. The card looks like ordinary work completion. | Identify linked task blocks in the projection and expose an explicit task-completion action, or clearly distinguish “complete this block” from “complete task.” Reuse existing task completion and block-link services. | Consistent domain meaning: a planning workflow should not imply work is finished when the task remains open. Date movement is synchronized by this change; completion remains a separate product gap. |
| HIGH | `src/renderer/src/features/shell/AppShell.tsx:323` | **Reproduced:** a native `openRoute` for an event only changes section; its ID is ignored. Opening a March event while January is visible leaves January visible with no inspector. Task/note branches also discard their IDs. | Route item IDs through the existing open-item commands; load and reveal the event's date. Make a native Today route actually reset the date. | A notification/reference must reach its target. Section-only routing repeatedly forces users to search again. |
| MEDIUM | `src/renderer/src/features/core/screens/calendar/CalendarRecurrenceDialog.tsx:5`; `src/main/services/coreStore.ts:2111` | Delete now safely offers occurrence and entire series. Deleting “this and future” remains unavailable. Whole-series gestures with stored edited/cancelled instances and date shifts involving complex selectors fail before writing, with guidance to change one occurrence. | Extend and test the existing recurrence service for future-series deletion and reviewed exception migration. Preserve earlier occurrences and exception identity before exposing those operations. | Recurrence workflow completeness. The unsafe choice was removed; this remains a capability gap rather than an exposed destructive action. |
| MEDIUM | `src/renderer/src/features/core/screens/calendar/useCalendarWheelNavigation.ts:5`; `CalendarView.tsx:275` | Horizontal/Shift-wheel navigation has no visible hint. Retention/future limits can stop scrolling or arrow navigation without explaining why. | Add a brief discoverable shortcut hint and a quiet boundary message, with disabled arrow states where appropriate. | Predictable navigation and feedback, particularly when a user reaches a configured limit. |

## Considered but rejected

| Location | Candidate | Rejected because |
| --- | --- | --- |
| Calendar services | Import the prototype event store and recurrence model | Would duplicate the live database, outbox, recurrence projection and undo; prototype data is illustrative. |
| Calendar scrolling | Keep every visited day/week mounted or prefetch months of events | Violates the existing viewport/cache bounds and makes work grow with navigation history. |
| Timeline cards | Enlarge every short event and drag handle to a 40px box | Makes adjacent times overlap and can eliminate the pointer move target. Preserve geometry and improve selected controls/keyboard access instead. |
| New menus | Load menu primitives through the globally shared event-chip module | Would pull additional menu code into initial renderer loading. The lightweight context is separate; menu presentation stays in the calendar feature. |
| Application appearance | Replace the design system or add extra entrance effects | The existing theme tokens, Radix primitives and restrained motion work. The remaining priorities concern clarity and behavior. |

- `corepack pnpm exec vitest run src/renderer/src/features/core/screens/calendar/useCalendarRangeLoader.test.tsx src/renderer/src/features/core/screens/calendar/calendarEventIndex.test.ts`: 6 passed. The deferred-loader test verifies one active request and only the latest queued viewport.
- Final database/sync run after recurrence hardening: **125 passed** (`corepack pnpm test:db`). The targeted recurrence suite passed all **10 tests** (`corepack pnpm exec vitest run src/main/services/googleRecurrence.test.ts --maxWorkers=1`). Gesture arithmetic tests cover timezone/DST movement, exclusive all-day ends, preserved grab offsets, minimum duration and keyboard resizing across midnight.
- `node /tmp/hcb-calendar-audit.mjs` launched an isolated Electron profile and exercised real controls/native IPC. Recorded evidence in `output/ui-review/calendar-product-observations.json`: task remained `active` after its block completed; native link left range at `2026-12-27` with no inspector; overflow Tab left the dialog. The temporary script and profiles were used only for audit, not as shipping code.
- Screenshots: `output/ui-review/event-context-menu.png`, `context-menu-narrow-{light,dark}-slow-motion.png`, `month-continuous-window.png`, `timeline-event-resized.png`, and the existing populated workflow captures. Screenshots are review evidence, not pixel baselines.
- The first standard `test:release-gate` run encountered five failures/timeouts in existing unit scenarios under concurrent machine load. Its build passed. `corepack pnpm test:unit --maxWorkers=1 --testTimeout=20000` then passed **230 tests** without loosening performance assertions; the two native-database suites skipped under Node were separately run under Electron.
- `corepack pnpm test:ui` passed **all 59 Electron tests**, including both populated-account scenarios. The final recurrence change is additionally covered by a rebuilt, focused interaction rerun below.

**Final validation completed:** the rebuilt application passed all **20 interaction tests** (`corepack pnpm test:ui tests/smoke/calendar-interactions.spec.ts`) after recurrence hardening. This includes explicit weekly weekdays, “this and future” movement, visible rejection of unsupported complex rules, and cancellation without opening an inspector. One earlier focused run encountered a detached element while preparing a gesture after a range refresh; preparation now waits for the replacement segment, without retrying the gesture or its write. The final run passed in full. Together with the 59-test full Electron run, 230-test serial unit run, 10-test focused recurrence run and 125-test final database/sync run above, all validation stages passed; the original aggregate release-gate command itself did not pass cleanly.

**Verdict: Block unrestricted daily-driver sign-off.** The requested interaction improvements are implemented; the HIGH findings above remain follow-up work. Not verified: live Google permission/rejection flows, signed installation, Windows/Linux desktop behavior, screen-reader interaction, and sustained 5k/10k performance. Passing local tests does not replace those checks.
